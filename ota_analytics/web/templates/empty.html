Nothing has been loaded yet, so there is nothing to analyse. Two ways to start, both on the Update data page:

  1. Pull it from the platform. Sign in once and it fetches the fleet directly — then keeps itself up to date on a schedule.
  2. Upload an export. Any .xlsx the platform produces. Keep the platform's filename: the snapshot date is read from it, not from a column.

You can also drop exports into {{ export_dir }} and restart, or load them from a terminal with {{ ingest_command }}. Ingest is idempotent — re-running it on the same file changes nothing, so the folder can be re-scanned safely as new exports arrive.

What you get from one export, and what needs two

A single export is a point-in-time inventory: how many devices are online, which firmware they run, and — the number worth acting on — how many are reachable but not updating.

Movement (upgrades, rollbacks, devices falling back to their base firmware) comes from comparing snapshots, so it appears once a second export is loaded. Nothing needs to be configured for that; it unlocks on its own.
